# /design-review - UI 검토

## 프로젝트 컨텍스트

> - **기획서 시안** (CLAUDE.md의 Confluence 링크): 12개 씬의 색·배치·문구 정본. 파스텔 그라디언트 배경 + 손글씨체 + 둥근 버튼.
> - **CLAUDE.md** 예산표: UI 스프라이트 512² · 배경 1024² · 씬당 텍스처 48MB
> - 디자인 토큰 파일은 없다. 색·폰트는 시안에서 읽어 **공용 프리팹/스타일 1곳**에 모으는지 본다.

## 역할 원칙

- 모바일 브라우저 세로 화면이다. 데스크톱은 보조.
- 시안과 다르면 지적하되, 시안이 구현 불가(폰트 라이선스·크기)하면 대안 제시.
- 예쁜 것보다 **가벼운 것**. 이미지로 만든 텍스트·버튼은 폰트·9-slice로 바꾸라고 한다.

## 워크플로우

### Phase 1: 현황
1. 변경된 씬을 MCP로 열어 Canvas 계층을 읽는다 (`Unity_RunCommand`로 트리 덤프).
2. 해당 씬의 시안 이미지를 사용자에게 받거나 기획서에서 확인.

### Phase 2: 레이아웃
- Canvas Scaler: `Scale With Screen Size` · 참조 1080x1920 · Match 0.5. 씬마다 다르면 지적.
- Safe Area 처리 (노치·하단 바). 상단 홈/설정 아이콘이 잘리지 않는가.
- 앵커가 절대 좌표로 박혀 있어 다른 비율에서 깨지는가.

### Phase 3: 시안 대조
- 배경 그라디언트 · 버튼 형태(둥근 노란 타원) · 손글씨 폰트 · 문구가 시안과 같은가.
- 12개 씬 공통 요소(뒤로가기 · 홈 아이콘 · 제목 말풍선)가 **공용 프리팹**인가, 씬마다 복제인가.

### Phase 4: 터치·접근성
- 터치 타겟 최소 88x88px(1080 기준). 하트 버튼은 더 크게.
- 텍스트 대비: 파스텔 배경 위 파란 글씨가 읽히는가 (WCAG AA 4.5:1). 안 되면 외곽선/배경 말풍선.
- 소리 슬라이더 등 조작 UI가 손가락으로 조작 가능한 크기인가.

### Phase 5: 에셋 예산
- 배경이 1024² 이하 압축인가. 그라디언트는 **작은 텍스처 + 스트레치**로 충분하다.
- 텍스트를 이미지로 넣었는가 → TMP 폰트로.
- 버튼 이미지가 9-slice인가, 크기별 별도 이미지인가.
- 씬 텍스처 합이 48MB 이하인가.

## 완료 상태
- **DONE**: 시안 일치, 예산 내
- **DONE_WITH_CONCERNS**: 통과하나 개선 권고
- **BLOCKED**: 텍스처 예산 초과 또는 터치 불가 크기
- **NEEDS_CONTEXT**: 해당 씬 시안이 비어 있음 (묘약·꽃밭은 시안이 빈 화면이다. 소식은 꽃밭 씬의 탭)

## 안전장치
- UI 변경 없는 diff는 "N/A - UI 변경 없음"으로 스킵
- 텍스처 예산 초과는 다른 항목이 다 좋아도 BLOCKED
- 시안이 없는 씬은 디자인을 지어내지 않고 NEEDS_CONTEXT
