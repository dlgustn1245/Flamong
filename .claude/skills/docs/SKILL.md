# /docs - 문서 동기화

## 프로젝트 컨텍스트

> 문서는 두 개뿐이다.
> - **README.md**: 씬 흐름 · 폴더 구조 · 서버 API · 데이터 모델 · 성장 규칙 수치 · 빌드 기록(크기·힙 피크). **단일 출처.**
> - **CLAUDE.md**: 규칙과 예산. 코드가 규칙을 바꾸면 여기도 바꾼다.
> `docs/` 폴더나 CHANGELOG는 만들지 않는다. 1인 프로젝트다.

## 역할 원칙

- 부정확한 문서는 없는 것보다 나쁘다. 확인 못 한 것은 "확인 필요"로 표시.
- 코드에서 읽을 수 있는 것(필드명·시그니처)은 적지 않는다. **왜 그렇게 정했는지**와 **수치**만.
- 예제 API 호출은 실제 엔드포인트와 일치해야 한다.

## 워크플로우

### Phase 1: 변경 감지
1. `git diff --name-only`로 변경 파일 확인.
2. 영향 매핑:

| 변경 | 갱신 절 |
|---|---|
| `Assets/Content/<씬>/01_Scenes/*.unity` 추가/삭제 | README 「씬 흐름」 + 「폴더 구조」 |
| `Server/routes/` 라우트 | README 「API」 (메서드 · 경로 · 요청/응답 필드) |
| `Server/schema.sql` | README 「데이터 모델」 |
| 성장·제한 수치 | README 「규칙」 + 기획서와 다르면 그 사실 |
| `ProjectSettings` (메모리·압축) | CLAUDE.md 예산표 |
| Web 빌드 실행 | README 「빌드 기록」 (날짜 · 크기 · 힙 피크) |

### Phase 2: 갱신
1. 해당 절만 고친다. 전수 재작성 금지.
2. 삭제된 씬·API는 문서에서도 지운다.
3. 링크·경로가 실재하는지 확인.

### Phase 3: 리포트
```
## Documentation Report
### 갱신: README 「절」 - 내용 / CLAUDE.md - 내용
### 불일치 발견: 문서 vs 코드 - 어느 쪽을 고쳤나
### 확인 필요: [항목]
```

## 완료 상태
- **DONE**: README·CLAUDE.md가 코드와 일치
- **DONE_WITH_CONCERNS**: 갱신했으나 확인 못 한 수치 있음
- **NEEDS_CONTEXT**: 규칙 변경 의도를 사용자에게 확인해야 함

## 안전장치
- 코드 변경 없이 문서만 고치는 요청은 무엇을 근거로 바꾸는지 먼저 확인
- 기획서(Confluence)는 고치지 않는다. 기획서와 다르게 구현했으면 README에 "기획서와 다름: 이유"로 남긴다
- 빌드 기록은 실제 빌드 결과만 적는다. 추정치 금지
