# /retro - 회고

1인 프로젝트 회고다. 협업 개선이 아니라 **다음 버전에서 무엇을 먼저 할지**를 정한다.

## 워크플로우

### Phase 1: 데이터
1. `git log --since=<마지막 태그>`: 커밋 수 · 파일별 변경 빈도.
2. README 「빌드 기록」: 버전별 다운로드 크기 · 힙 피크 추이.
3. README 「미루는 것」 목록과 실제 구현 대조.

### Phase 2: 패턴
- **핫스팟**: 5회 이상 바뀐 파일. 씬 컨트롤러가 반복해서 바뀌면 Session/ApiClient로 옮길 것이 있다는 신호.
- **예산 추이**: 다운로드·힙이 버전마다 늘면 어느 에셋이 원인인지.
- **규칙 위치**: 클라에 들어간 규칙 계산이 누적됐는지 (`/arch-review` 결과 참조).
- **미룬 것**: 두 버전 이상 미룬 기능은 지울지 결정.

### Phase 3: 리포트
```
## Retro: vX
### 기간 · 커밋 N · 변경 파일 N
### 잘한 것 (Keep)
### 문제 (Problem) → 영향
### 다음 버전에서 (Try)
### 핫스팟 Top 5
### 예산 추이: 다운로드 N→N MB · 힙 N→N MB
### 미룬 기능: 계속 미룸 / 삭제 / 다음 버전
```

## 완료 상태
- **DONE**: 다음 버전 우선순위 도출
- **DONE_WITH_CONCERNS**: 데이터가 얇아 확신 낮음
- **NEEDS_CONTEXT**: 빌드 기록이 없어 예산 추이를 볼 수 없음

## 안전장치
- 커밋 5개 미만이면 "아직 이릅니다"
- Keep을 반드시 포함
- 예산 추이는 실제 빌드 기록만. 추정 금지
